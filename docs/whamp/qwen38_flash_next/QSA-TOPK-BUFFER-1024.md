# Qwen3.8 QSA top-k buffer allocation

## Decision

Promote `max_num_batched_tokens=1024` for the Intel AutoRound Qwen3.8
EP=4 profile on server60.

This one-variable configuration change halves twelve persistent QSA top-k index
buffers. It reclaims exactly 100,810,752 bytes per GPU, raises the automatically
fitted context from 148,400 to 156,400 tokens, preserves decode performance,
and keeps 94.7% of the matched cache-busted prefill rate. The final service uses
the original image, model, BF16 QSA cache, quantized CPU PLE, vision stack, and
expert-parallel layout.

This does not implement FP8 or Q4 QSA cache. The current cache remains BF16.

## Causal result

The QSA implementation registers one INT32 top-k index buffer for each of the
12 full-attention layers. Each buffer has shape
`[max_num_batched_tokens, 2051]`.

| Allocation | Control | Candidate | Change |
| --- | ---: | ---: | ---: |
| QSA top-k buffers per GPU | 201,621,504 B | 100,810,752 B | -100,810,752 B |
| All registered model storage per GPU | 19,917,943,320 B | 19,817,132,568 B | -100,810,752 B |

The total registered-storage change equals the QSA top-k change exactly. No
other registered model storage moved in the diagnostic A/B.

The production startup reported 1.95 GiB available for KV cache and fitted
156,400 tokens. The control had 1.85 GiB available and fitted 148,400 tokens.
The gain is 8,000 tokens, or 5.39%.

## Matched performance

Both arms used 3 warmups plus 5 measured 256-token decode runs and one warmup
plus 3 measured 17,825-token cache-busted prefill requests.

| Metric | Control 2048 | Promoted 1024 | Change |
| --- | ---: | ---: | ---: |
| Decode, mean | 44.07 tok/s | 43.94 tok/s | -0.29% |
| Decode, population CV | 1.75% | 2.44% | +0.69 pp |
| Prefill, mean | 1,636.62 tok/s | 1,549.89 tok/s | -5.30% |
| Prefill, population CV | 0.07% | 0.36% | +0.29 pp |
| Concurrency-2 aggregate decode | not measured in control | 54.72 tok/s | n/a |
| Concurrency-2 mean per stream | not measured in control | 35.29 tok/s | n/a |

The candidate passed the preregistered floors of 95% control decode, 90% control
prefill, and at least 5,000 additional fitted tokens.

The lower prefill budget increases chunk count for large prompts. The measured
5.3% prefill loss is the accepted cost for 8,000 additional context tokens and
96.14 MiB more KV room per GPU.

## Delivery

The accepted production contract is preserved as
[evidence/qwen38-qsa-1024-20260829/production.yml](evidence/qwen38-qsa-1024-20260829/production.yml).
The unchanged control contract and tested rollback are in the same evidence
directory. `analysis.json` is regenerated by `analyze_qsa_ab.py` from the raw
four-rank reports and acceptance results.

The next capacity phase is native Q8 and Q4 QSA cache work. The pinned QSA path
currently rejects cache quantization, so that phase requires new SM86 storage,
write, read, attention, allocation, graph, numerical, and rollback contracts.
