# IQ1 GPU-free performance preparation — 2026-08-21

Status: implemented and compile-validated on server60 (CPU-only, no GPU
contact). **No performance claim is established** — every number here is a
source-level expectation. The gates below must pass in an authorized GPU
window before any of this reaches a candidate image.

## Why

Measured Unsloth UD-IQ1_S/IQ1_M decode (40.80 / 44.79 engine tok/s) runs at
roughly half the Antirez GGUF-TP result (76.7 tok/s). Off-GPU source review
attributed the gap hypothesis-wise to implementation quality rather than
serialized size: the IQ2_XXS/Q2_K kernels received measured DP4A, DwarfStar,
and grouped-MMA tuning, while the IQ1/IQ3/MXFP4/Q4_K/Q5_K/Q6_K kernels were
correctness-validated only.

## Changes (Whamp/vLLM)

- `feat/gguf-tp-iq1-unsloth` commits `e7982b484` (kernels) and `5b563e50e`
  (benchmark).
- Production-compatible lineage `deploy/gguf-tp-iq1-unsloth-633815f` commits

### 1. Parity-split IQ1 grid tables (`iq1_iq3_tables.cuh`)

The hot path previously consumed each 32-bit grid word through
`pack_iq1_grid_parity` — 8 shifts + 8 ORs per dot product — then multiplied
the packed bytes by the scale code (16 LOP3s). Two changes:

- Generated `kIq1SGridEven[2048]` / `kIq1SGridOdd[2048]` at table-generation
  time, byte-identical to `pack_iq1_grid_parity(grid, 0/1)`. Verified against
  the packing function on spot entries; the generator IS the packing function.
- Moved `kIq1SGrid`, both split tables, `kIq3XXSGrid`, and `kIqSigns` from
  `__constant__` to `__device__` storage. Constant-bank reads serialize when
  lanes in a warp read different addresses; every lane reads a different
  table index here, so the cached-global path (`LDG.E.CONSTANT`, L1-backed)
  is the correct choice.

### 2. Hot-loop consumption (`iq1_iq3_matvec.cu`, `iq1_grouped.cu`)

Raw/indexed kernels now index the split tables directly; the grouped kernel
stores pre-split words in shared memory at tile-load time, so fragment
decoding inside the MMA loop is one table word plus the scale multiply.
Net removal: ~24 integer ops per 32-value dot in raw/indexed, ~16 per
fragment in grouped.

### 3. Q4_K/Q5_K vectorized group dot (`q456_k_matvec.cu`)

Q4_K/Q5_K blocks are 144/176 bytes, so every quant segment is 16-byte
aligned by format geometry. The group dot now:

- loads the 32-byte quant window as two `uint4`s (was 32 byte loads),
- applies the Q5 high-bit plane branchlessly:
  `packed |= (load_u32(block+16+4p) >> group_index & 0x01010101) << 4`
  (was a per-byte load + data-dependent branch; the bit-plane-per-position
  semantics `high_bits[element] bit group_index` are preserved exactly),
- keeps scale/min decode and the d/dmin accumulation identical.

Q6_K keeps byte loads: its 210-byte block stride cannot guarantee alignment
for wider loads, and it covers only shared-down (one op/layer).

### Host differential proof caught a real kernel bug

Applying the testing discipline that the IQ1 lane-mapping incident motivated:
a standalone C++ harness compiles the real modified header as plain code
against verbatim copies of the pre-rewrite arithmetic (CUDA shims: `__dp4a`,
half conversion) and proves three things:

1. All 2,048 `kIq1SGridEven/Odd` entries match `pack_iq1_grid_parity`
   exactly (exhaustive, not sampled), and the base tables are byte-identical
   to the git parent revision.
2. 200,000 randomized Q4_K/Q5_K group-dot cases agree **bit-exactly**
   between old and new implementations.
3. Adversarial patterns (all-zero/all-ones/nibble planes, single-bit weight
   and activation planes, every group index, per-element high-bit sweep)
   agree bit-exactly.

The harness failed on its first run: the vectorized group dot loaded two
`uint4` words at offsets +0 and +8, covering bytes 0–23 of the 32-byte
quant window and silently dropping bytes 24–31. Fixed in Whamp/vLLM commits
`cd2fc29a2` (canonical) and `a04254a00` (production-compatible); after the
fix all checks pass. This bug would have cost a rebuild plus a GPU-window
round trip to find, and it validates keeping synthetic-oracle distrust as a
testing policy for this project.

Tooling: `.research/gguf-tp-iq1/host-differential/` (harness, generated
old-tables include, reproduction command in README).

## Expected effect (hypothesis, not measurement)

Decode is dominated by weight streaming of the routed experts. The IQ1_S
gate/up path previously spent a large share of its inner loop on integer
bit manipulation between 1-bit table lookups and DP4A; removing ~24 ops per
dot and taking table reads off the serialized constant path should raise
the achieved bandwidth of the ~19.9–21.3 GiB/rank routed payload toward the
IQ2_XXS kernels' measured ~346–358 GB/s class. The Q5_K win additionally
covers shared gate/up and `q_a` partitions. Whether this closes a meaningful
fraction of the ~2× decode gap is exactly what the pending GPU gates must
answer; if kernel throughput was not the binding constraint (e.g. the
mixed-linear launch/intermediate overhead hypothesis dominates instead),
these changes will show flat and the next seam is the per-call
activation-quantize/concatenate chain in `GGUFDSV4LinearMethod`.

## Rejected / deferred in this pass

- Q6_K and IQ3_XXS vectorization: block strides 210/98 break 4-byte
  alignment; paired-block funnel-shift loads add risk without measurement.
- `multiply_packed_bytes` elimination in grouped MMA: the scale multiply
  cannot fold into activations (shared per tile, not per row) and int8
  overflow forbids hoisting it out of the dot.
- Mixed-linear intermediate-tensor/workspace reduction: behavior-affecting
  production change, deferred until the timing harness attributes it.

## Mixed-linear launch-chain reduction (GPU-free pass 2, 2026-08-21)

The deferred "per-call activation-quantize/concatenate chain" seam is now
implemented for the all-K-quant case:

- `q456_k_matvec.cu` / `q456_k_grouped.cu`: raw-matvec and grouped-matmul
  kernels address output rows through the output tensor's row stride
  (`output[token * stride + row]`); launchers accept any 2D output with
  unit-stride columns instead of requiring full contiguity. Contiguous
  outputs behave identically (`stride(0) == size(1)`), so existing callers
  and tests are unchanged.
- `GGUFDSV4LinearMethod.apply`: when every partition is K-quant (shared
  gate/up and down on Unsloth IQ1 artifacts), partitions write directly
  into column slices of one combined FP32 buffer and convert to BF16 once.
  Per linear call this removes P-1 conversions plus the concatenation
  (3 kernels/layer across gate/up + down); the mixed K-quant + Q8_0
  compressor path is unchanged. Values are bit-identical: each element is
  rounded FP32->BF16 exactly once either way.
- New bit-exact strided-vs-contiguous GPU test for both entry points
  (3 cases; execution pending an authorized GPU window).

Evidence: both edited translation units compile clean for sm_86 against
the `iq1-ed311edc-fp4` image torch headers (CPU-only nvcc, no GPU
processes; `--expt-relaxed-constexpr` required outside CMake). CPU suites
(`test_gguf_dsv4.py` x2) pass 20/20; native-format collection is now 43
GPU tests. Commits: Whamp/vllm `9e31832cc` (feat/gguf-tp-iq1-unsloth) and
`5f7b4d6c6` (deploy/gguf-tp-iq1-unsloth-633815f).

Expected effect (estimate, unmeasured): ~129 fewer small kernels/token
(~3/layer x 43 layers), roughly 1-2% decode at the current ~44.8 tok/s;
the GPU benchmark harness and native-format suite remain the gates.

Also audited and closed without change: the hierarchical all-reduce path.
It is already a single Triton launch with a one-shot two-sync-round
algorithm for decode-sized (8 KiB) messages and a measured one/two-shot
crossover (~48 KB on 2x4 A800 PCIe; server60 value is INSTANCE). The
measured ~23.3 us/layer is near the two-phase lower bound for 4 ranks
without switch multicast; remaining fat there is launch skew, not
algorithm.

## Maintainability pass (GPU-free, 2026-08-21)

Behavior-preserving cleanup while GPU gates remain pending:

- `GGUFDSV4LinearMethod` / `GGUFDSV4MoEMethod`: the copy-pasted
  per-format if/elif dispatch chains are now explicit dispatch tables
  keyed by source type. Table values are custom-op names resolved lazily
  through `_registered_op`, so importing the module never requires the
  CUDA extension (eager `torch.ops._C` attribute access raises in CPU
  environments) and every op name stays greppable. Error messages are
  unchanged. Adding a future expert format becomes one table entry.
- The Q2_K grouped-down op's missing trailing `topk` argument (it
  predates its siblings) is documented at its single call site instead
  of being buried in an elif chain.
- BF16-to-Q8_1 activation quantization deduplicated into
  `_quantize_bf16_activation`; `block_bytes`/`block_elements` constexpr
  helpers marked `__host__ __device__` in all nine kernel translation
  units.
- Test weight generators deliberately left duplicated: their reference
  decoders are the numerical oracle, and DRY-ing an oracle weakens it.

Evidence: all nine kernel TUs compile standalone for sm_86 with default
nvcc flags (no `--expt-relaxed-constexpr`); CPU suites pass 20/20 on
both vLLM lines; native-format collection remains 43 tests. Commits:
Whamp/vllm `408aebad0` (feat/gguf-tp-iq1-unsloth) and `8693e28b7`
(deploy/gguf-tp-iq1-unsloth-633815f). Net -74 lines.

## Property-based planner laws (GPU-free, 2026-08-21)

New Hypothesis suite `tests/model_executor/model_loader/test_gguf_dsv4_plan_properties.py`
(6 laws, pure Python, CPU-executable) searches the TP load planner over
generated DeepSeek V4 inventories — random layers, quant types, shapes,
TP degrees 1–8:

1. Every tensor's bytes are read exactly once across TP ranks
   (replicated kinds: fully on every rank).
2. Source spans never overlap within a rank.
3. Stacked fused targets are contiguous and disjoint.
4. INPUT_BLOCKS/OUTPUT_ROWS shards respect block/row alignment.
5. Unshardable shapes raise ValueError (TP ≥ 2).
6. Unsupported tensor names fail closed.

The shard-kind oracle table is transcribed from TP-MAPPING.md, not from
production rules. Discrimination proven with two temporary counterfeits:
dropping the OUTPUT_ROWS TP-rank offset tripped law 1; corrupting the
INPUT_BLOCKS rank offset tripped law 4; green after restore. Generator
triage during development caught two invalid-inventory artifacts
(independent offsets breaking real-GGUF disjointness; an F32 cursor
arithmetic bug), not production defects. CPU suites: 23 loader/quant
tests pass on both vLLM lines; GPU collection unchanged at 43.
Commits: Whamp/vllm `37460d3dc` and port cherry-pick; pushed to both
branches.
